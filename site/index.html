A directory where an organization publishes its own interconnection capability, so that two organizations can check compatibility before they build a link. It holds signed pointers, not permissions. The reader checks every signature and digest against keys it bound outside the directory.

What it is

Modeled on PeeringDB, the database internet network operators consult before turning up a BGP session. Its only job is to stop two competent parties from misconfiguring each other.

Advisory, never authoritative. Being listed grants access to nothing.

Pointers, not permissions

The expected entry is a signed pointer record: where the party's signed package can be fetched, and that package's SHA-256. A counterparty fetches the package, verifies its signatures against its own trust store, and recomputes the digest. The directory is an input to none of those checks.

Writes are trust on first use

The first PUT for a sovereign_id binds the key it presents, the same shape as an SSH host key. It stops one party overwriting another's entry and establishes nothing about identity. Parties bind each other's keys over a channel they already trust.

Federation works with it switched off

Two parties compose independently with the same versioned tool and compare one digest. That needs no server and works with an entirely offline partner. Nothing in the federation mechanism may come to require the directory.

What it refuses

Reachability, release sets, accepted limits and cut procedures are sovereign operational detail. They move directly between two parties, not through a directory that everyone can read. An entry carrying any of the three offer blocks is refused with HTTP 422 and a message saying so. There is no flag to relax it.

A pointer record carries exactly six members; anything else, such as a key, an identity, a contact or an offer, is refused with HTTP 422.

Not built, on purpose

  • No ranking, matching or brokering: no "compatible partners" endpoint, no sort, no filter. TestNoRankingOrMatchingEndpointExists enforces it.
  • No accounts, organizations, roles or approval workflow.
  • No enforcement: an expired package is still served, marked X-Saltlick-Expired: true.

Run it

Go 1.25 to build. The SQLite driver is pure Go, so the binary is static and needs no cgo, no libc and no external database. serve binds 127.0.0.1:8080; the expected deployment puts it behind a public TLS proxy or load balancer.

make build                        # ./saltlick
make check                        # gofmt, go vet, go test: the Go half of CI
./saltlick serve -db saltlick.db  # binds 127.0.0.1:8080

saltlick keygen -out xaa          # an Ed25519 keypair in the encoding the API expects
saltlick sign -key xaa.key -package xaa.pointer.json -out xaa.pointer.signed.json
